# Všeprotisk — Upgates e-shop design system (Hermes project rules)

Project: pixel-perfect storefront redesign on Upgates, powered by Penpot designs,
external override CSS. The user is a **designer, not a developer**.

## Architecture (settled — do not regress to alternatives)

- **Design source of truth:** Penpot. User exports design-tokens JSON + per-screen
  images/SVG. I consume those.
- **Implementation is a single-owner, FULL override layer** — NOT Upgates variables
  as the primary lever. Rationale (user-driven): the Upgates variables/Designer
  admin are entangled with editor state I can't own, which splits the dev pipeline.
  The override layer bypasses that and is the one surface I fully control.
- **How we inject:** external SCSS/CSS (pasted into `custom.scss` or loaded via
  `<head>`), EVERYTHING inside `@layer override { … }` so the layer wins against
  the theme deterministically. Verified present in the platform's `_critical.scss.css`.
- **Update safety:** Upgates' staging/test layer gives an audit window before live.
  Use it to re-audit selectors + DOM after every platform/theme update. Keep a
  lightweight class-check (list of classes each override references → verify they
  still exist) for catching subtle breakage a visual pass misses.

## Non-negotiables (do not skip)

1. **Ask before scaffolding/build tools** during strategy work. The user values
   research + validated strategy over unexpected artifacts. Only build what's been
   explicitly agreed.
2. **Designer-first:** never edit theme template files; prefer overlay CSS.
   Editing templates is a deliberate escalation with update-maintenance cost.
3. **No `!important` towers; no full-theme rewrites.** Restraint minimizes the
   maintenance surface.
4. **Verify every rule by inspect:** right-click → Inspect → read computed style →
   write override → re-check. Re-inspect after every theme update (the survival
   contract).
5. **Target only theme selectors you've inspected, never guessed.**

## Conventions

- All custom values via the team's own `--vsp-*` custom properties (never raw
  hex/px in rules). One token file re-skins the whole shop.
- One labeled section per visual concern (buttons, cards, header, …) in the
  override file.
- Files on the VPS are invisible to the user — present output inline in chat,
  or use `references` guidance for transferring.
